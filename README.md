# dev-cycle

Навык для Codex, который помогает превратить обсуждения, интервью и «хотелки» в пользовательские истории, а затем связать их с критериями приёмки, моделью предметной области, проектными решениями, задачами и тестами.

Модель хранится в `docs/model/` проекта. У историй, критериев и других элементов постоянные идентификаторы. По ним можно найти, откуда взялось решение и что пересмотреть при изменении требований. После каждого аналитического шага агент показывает черновик, результаты проверки и развилки. Переход к следующему шагу требует утверждения текущего.

## Попробовать без установки навыка

В [учебном примере](examples/equipment-booking/README.md) сотруднику нужна камера для съёмки, а администратор должен исключить двойное бронирование слота. В репозитории есть вымышленный разговор, модель и четыре теста. Для примера достаточно Python 3.9+ без сторонних библиотек.

Из корня репозитория:

```sh
python3 dev-cycle/scripts/trace.py --model examples/equipment-booking check
python3 dev-cycle/scripts/trace.py --model examples/equipment-booking impact USRSTR-2/ACPT-2
python3 dev-cycle/scripts/trace.py --model examples/equipment-booking tests --slice booking
(cd examples/equipment-booking && python3 -m unittest -v)
```

`check` проверяет структуру и трассировку. `impact` ищет элементы, связанные с изменяемым критерием. `tests` находит метки покрытия, а `unittest` запускает сами тесты.

## Установить в Codex

Скопируйте папку `dev-cycle/` в `.agents/skills/` рабочего проекта. Для личной установки можно использовать `~/.agents/skills/`. Итоговый путь должен заканчиваться на `dev-cycle/SKILL.md`. Вместе с `SKILL.md` нужны инструкции шагов, шаблоны, справочные материалы и скрипт. [Документация Codex о навыках](https://learn.chatgpt.com/docs/build-skills)

Откройте Codex в рабочем проекте, выберите `$dev-cycle` и дайте ему исходный материал. Например:

```text
$dev-cycle stories Разбери заметки из meeting.md. Подготовь пользовательские
истории и вопросы по спорным решениям. Остановись после первого шага.
```

Первый результат — истории с наблюдаемым результатом и источником, вопросы в `INDEX.md` и, если они обнаружены, риски в `risks.md`. После согласования историй следующий шаг добавляет проверяемые критерии и нефункциональные требования. Дальше идут роли и агрегаты, связи, процессы, состояния, жизненные циклы и метрики. Из согласованной модели можно взять срез для проектирования, реализации и приёмки.

## Как помочь развитию

Для предложения по методике опишите исходный материал, ожидаемый результат шага и место, где возникла развилка. Для ошибки в `trace.py` приложите минимальный пример модели, команду и вывод. Для сравнения поведения агентов добавьте название клиента и пример вызова.
