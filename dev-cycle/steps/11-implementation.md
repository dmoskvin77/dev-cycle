# Шаг 11. Реализация

Начинается только по прямой просьбе — «делай», «поехали», «задача 3».

- Бери задачи по порядку, если не сказано иначе.
- Закончив задачу, **сразу** ставь `[x]`. Отметка после всей пачки
  бесполезна: если сессия прервётся, состояние потеряно.
- Не бери следующую задачу молча, если задача оказалась крупнее, чем
  выглядела. Скажи об этом.

Три привычки, которые держат трассировку до кода:

- **Метка у теста.** Тест помечается комментарием с номером критерия или
  НФТ, который он проверяет: `// verifies: USRSTR-3/ACPT-2`. Ставится
  в момент написания теста, а не потом. По этим меткам шаг 12 видит,
  что проверено.
- **Номер задачи в коммите.** Сообщение начинается с номера:
  `TASK-7: добавить метод X`. От строки кода через `git blame` можно дойти
  до задачи, от неё — до критерия и истории.
- **`[x]` после зелёных тестов.** Отметка на непроходящих тестах врёт так же,
  как модель, разошедшаяся с кодом.

Если при реализации модель разошлась с кодом — правится документ, а не
только код (раздел «Когда модель расходится с реальностью» в SKILL.md).

Когда отмечена последняя задача среза — скажи об этом и предложи шаг 12.
