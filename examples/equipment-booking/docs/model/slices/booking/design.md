# Проектирование среза «Бронирование одного слота»

**Состав среза:** USRSTR-1, USRSTR-2

### DES-1. Хранить заявки на один слот в памяти

**← Обоснование:** USRSTR-1/ACPT-1, USRSTR-1/ACPT-2, USRSTR-2/ACPT-1, USRSTR-2/ACPT-2, AGGR-1/TR-1, AGGR-1/TR-2, MTR-1

В booking.py класс BookingSlot хранит статусы заявок на один заранее выбранный слот. Интерфейс состоит из подачи заявки, чтения статуса по номеру и подтверждения. Подтверждение проверяет роль и наличие уже подтверждённой заявки. Аргумент роли имитирует результат проверки полномочий вызывающей стороны.

Альтернативой было постоянное хранилище с транзакцией. Для учебного сценария из последовательных вызовов достаточно памяти процесса. MTR-1 проверяется по итоговым статусам заявок после попытки подтвердить вторую заявку.

## Как проверяется

| Критерий | Метод | Проверка |
|---|---|---|
| USRSTR-1/ACPT-1 | тест | Подача возвращает номер и начальный статус |
| USRSTR-1/ACPT-2 | тест | Чтение по номеру возвращает новый статус после подтверждения |
| USRSTR-2/ACPT-1 | тест | Сотрудник получает отказ, администратор подтверждает заявку |
| USRSTR-2/ACPT-2 | тест | Второе подтверждение отклоняется, обе заявки сохраняют статус |
